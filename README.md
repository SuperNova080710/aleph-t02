# BUG DODGER · 30초의 시스템 방어

로그인 없이 브라우저에서 실행되는 버그 회피 게임입니다. 파란 로봇을 움직여 빨간 버그와 충돌하지 않고 30초를 버티세요.

## 실행

Node.js 20 이상에서 별도 빌드 없이 실행합니다.

```bash
npm start
```

`http://127.0.0.1:4173`에서 엽니다. ES 모듈을 사용하므로 HTML 더블클릭(file://) 대신 HTTP로 실행하세요.

## 조작

| 동작 | 입력 |
|---|---|
| 좌우 이동 | ← / → 또는 A / D, 화면 화살표 버튼 |
| 일시정지 / 재개 | P 또는 버튼 |
| 새 게임 | R 또는 버튼 |
| 시작 / 다시 시작 | 화면 중앙 버튼 |

- 한 번의 이동 이벤트가 24px 이동 한 번으로 반영됩니다. 가장자리에서만 좌표를 제한합니다.
- 키를 길게 누르면 OS가 보내는 반복 이벤트마다 이동합니다. P/R의 자동 반복은 무시합니다.
- Tab으로 버튼/설정을 선택하고 Enter/Space로 조작할 수 있습니다. 입력창에서는 게임 단축키를 실행하지 않습니다.
- 창·탭 이탈 시 자동 일시정지합니다. 돌아온 뒤 직접 재개합니다.
- 0.5초를 초과하는 프레임 공백에서도 자동 일시정지하여 복귀 직후의 즉사나 시간 건너뛰기를 막습니다.

## 구현

- 프레임 시간 기반 진행과 1/120초 이하 충돌 서브스텝
- 기본 낙하 배수 **1.0×**, 생성 간격 **0.85초** 고정
- 성공/실패 때만 0.9초 종료 효과; 움직임 줄이기와 OS 설정으로 즉시 중단
- 브라우저 저장 검증 및 손상·빈 값 복구; 저장이 차단되어도 실행
- 최근 200판 및 최고 기록/횟수/설정 보존, 새 판 데이터 분리
- PLAY LAB: 같은 seed 10쌍으로 속도 하나만 바꾸는 실제 플레이 기록
- 외부 폰트·CDN·분석 서비스·인증·서버 API 없이 실행

## 난이도 결정

자동 파일럿의 같은 조건 20회 결과입니다. 사람 플레이 기록이 아닙니다.

| 설정 | 판 수 | 생존 중앙값 | 생존 범위 | 성공 | 충돌 |
|---|---:|---:|---:|---:|---:|
| A: 1.0× | 10 | 30초 | 3.683–30초 | 6 | 4 |
| B: 0.8× | 10 | 22.9165초 | 4.183–30초 | 3 | 7 |

이 파일럿에서 중앙값이 높고 충돌이 적었던 **1.0×**를 기본값으로 선택했습니다. 느린 버그는 화면에 오래 머무르므로 속도 감소가 반드시 난이도 감소를 뜻하지 않습니다. 사람에게도 같은 결과가 나온다는 주장은 하지 않습니다. 필요하면 PLAY LAB에서 사람 플레이 20판을 추가하고 최종 판단을 기록할 수 있습니다.

## 검증 재현

```bash
npm ci
npx playwright install chromium
npm test
npm run experiment
```

터미널 하나에서 서버를 켜고, 다른 터미널에서 브라우저 검사를 실행합니다.

```bash
npm start
```

```bash
npm run test:browser
npm run test:soak
```

기능 검사는 시간을 제어하는 자동 검사입니다. `test:soak`은 시간 가속 없이 실제 600초 동안 조작과 재시작을 반복합니다. 테스트에서만 상태 읽기용 코드를 삽입하며, 배포 코드에는 테스트 API가 없습니다.

## 배포

정적 사이트 호스팅에서 프로젝트 루트를 게시합니다. 필수 파일은 `index.html`, `style.css`, `src/`입니다. Vercel은 Framework Preset **Other**, Build Command 비움, Output Directory **.**로 설정할 수 있습니다. GitHub Pages는 브랜치 루트를 게시할 수 있습니다. 기존 main을 보존하고 새 브랜치에서 검토합니다.

**이 브랜치의 공개 배포 주소는 아직 검증하지 않았습니다.** 소스가 공개인 것과 배포 게임이 로그인 없이 열리는 것은 별도 조건입니다. 제출 전 실제 배포 URL을 새 시크릿 창에서 확인하세요.

## 이슈

GitHub 연결은 브랜치/코드 쓰기가 가능하지만 Issues 생성에는 403을 반환했습니다. 기능별 본문 3개를 [docs/issues](docs/issues)에 준비했습니다. Issues 쓰기 권한이 있는 GitHub CLI 세션에서 아래 명령으로 중복 없이 생성할 수 있습니다.

```bash
bash scripts/create-issues.sh
```
